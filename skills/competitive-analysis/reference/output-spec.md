# Output Specification · 报告结构 + 验收 + Source 格式

## 报告 7 段结构

按以下顺序产出，**每段独立完成再写下一段**。

### 1. 执行摘要（Executive Summary）

3-5 句话，覆盖：
- 目标产品所在赛道与竞品格局
- 目标产品相对位置（领先 / 跟随 / 差异化）
- 最关键的 1-2 个洞察

**注意**：如果使用了澄清默认值，**在执行摘要前一行声明**：
> "本报告按 PM 视角 / 全球市场 / 5 个竞品的默认假设产出。"

### 2. 竞品概览表（Competitor Overview）

| 产品 | 公司 | 定位 | 目标用户 |
|------|------|------|---------|
| ... | ... | 一句话定位 | ... |

### 3. 功能矩阵（Feature Matrix）

横向对比 5-8 个核心功能：

| 功能 | 目标产品 | 竞品A | 竞品B | ... |
|------|---------|------|------|-----|
| 功能 X | ✅ | ✅ | ⚠️ | ... |

- ✅ 完整支持
- ⚠️ 部分支持 / 有限
- ❌ 不支持
- ❓ 信息不足

### 4. 定价矩阵（Pricing Matrix）

| 产品 | 免费版 | 个人付费 | 团队版 | 企业版 |
|------|-------|---------|--------|--------|
| ... | $0 / 5 docs | $10/月 [URL] | $20/user/月 [URL] | Contact sales |

- **必须带 source URL**（官网 pricing 页优先）
- 价格未公开 → 标 "未公开"，不要猜

### 5. 用户痛点对比（User Pain Points）

| 产品 | 好评 | 差评 / 痛点 |
|------|------|-----------|
| ... | ✓ 用户称赞... | ✗ 用户抱怨... |

- 每个竞品好评 / 差评各 ≥ 1 条
- 差评 / 痛点**不可空**；若公开评价不足，显式声明 "评价不足"
- 引用来源（Reddit / G2 等）inline URL

### 6. 目标产品 SWOT

**只对目标产品做 SWOT，不是所有竞品**。

| 类型 | 内容 |
|------|------|
| Strengths | 至少 2 条，基于第 3 段功能矩阵推导 |
| Weaknesses | 至少 2 条，基于第 5 段差评推导 |
| Opportunities | 至少 2 条，市场机会 / 未被满足需求 |
| Threats | 至少 2 条，基于强竞品 / 趋势风险 |

**S/W/O/T 每项不可空**。

### 7. 战略建议（Strategic Recommendations）

3-5 条**可执行**建议：

- 不要写"加强用户体验"这种空话
- 要写"针对 Copilot 的 SaaS 销售优势，做 battlecard 强调 IDE 级 agentic editing 体验"这种具体的
- 每条建议引用支撑事实（如"基于第 5 段 Copilot 用户抱怨..."）

## Source 最小结构

每个引用来源**至少**记录：

```json
{
  "url": "https://example.com/pricing",
  "title": "Pricing page",
  "publisher": "Example",
  "fetched_at": "2026-05-14T19:00:00+08:00",
  "type": "pricing",
  "used_for": ["pricing", "feature_matrix"]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `url` | ✅ | 完整 URL，真实可访问 |
| `title` | ✅ | 页面标题 |
| `publisher` | — | 来源机构 |
| `fetched_at` | ✅ | ISO 8601 时间戳 |
| `type` | — | `official_page` / `pricing` / `blog` / `review_site` / `social` / `news` / `other` |
| `used_for` | ✅ | 本来源被引用于哪些字段，如 `["pricing", "negative_reviews"]` |

**报告正文**：用 inline URL（如 `[example.com/pricing]`）即可，无需重复完整结构。
**项目工程实现**：映射为 `source_id`，注入 `sources_pool`。

## Output Acceptance Criteria · 验收标准 {#acceptance}

一次合格输出必须满足：

| # | 验收项 | 标准 |
|---|--------|------|
| 1 | 竞品数量 | ≥ 3 个，默认 5 个 |
| 2 | 报告段齐全 | 7 段全部包含 |
| 3 | 来源覆盖 | 每竞品 ≥ 2 来源，其中 ≥ 1 个 `type=official_page` 或 `pricing` |
| 4 | 定价来源 | 优先官网 pricing 页；未公开则显式标"未公开 / 信息不足" |
| 5 | 差评非空 | 不可省略；评价不足须显式声明 |
| 6 | 报告语言 | 中文；产品名 / 公司名 / 套餐名保留英文 |
| 7 | 默认值声明 | 若用了澄清默认值，报告开头必须显式声明 |
| 8 | SWOT 完整 | S/W/O/T 每项 ≥ 2 条 |
| 9 | 战略建议 | 3-5 条，每条引用支撑事实 |

跑完自检：逐条对照验收清单，不达标的修复或显式声明缺漏原因。
