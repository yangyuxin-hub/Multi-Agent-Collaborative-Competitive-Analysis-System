# 项目研究问题清单

本项目实施前/中需要回答的核心问题。按 6 类 25 个问题组织，每个问题包含背景、建议解法与状态。

---

## 一、Agent 编排与协作（最核心）

### Q1. LangGraph 到底怎么编排 6 个 Agent？
- **背景**：用 StateGraph 还是 MessageGraph？状态如何在 Agent 间传递？
- **建议解法**：用 `StateGraph + TypedDict`，每个 Agent 读取/修改共享 state
- **状态**：待研究
- **优先级**：🔴 P0

### Q2. 并行执行怎么实现？
- **背景**：竞品对比 + 洞察分析需要并行，LangGraph 怎么写？
- **建议解法**：用 `add_edge` 加两条平行边 + `wait_for_all` 节点合并
- **状态**：待研究
- **优先级**：🔴 P0

### Q3. Agent 失败后流程怎么走？
- **背景**：信息采集失败，后续 Agent 是直接跳过还是降级？
- **建议解法**：用 conditional_edge，失败时走"降级路径"，标记数据缺失但继续
- **状态**：待研究
- **优先级**：🔴 P0

### Q4. Agent 之间如何避免幻觉传播？
- **背景**：上一个 Agent 输出错的，下一个会基于错误继续生成
- **建议解法**：抽取阶段强制要求"非空字段必须有 source 引用"，否则置 null
- **状态**：待研究
- **优先级**：🔴 P0

## 二、信息采集与抽取

### Q5. 怎么自动识别一个产品的 5 个竞品？
- **背景**：用 LLM 直接问还是搜 "alternatives to X"？
- **建议解法**：双路召回——LLM 知识 + Tavily 搜 "X alternatives / competitors"，去重合并
- **状态**：待研究
- **优先级**：🔴 P0

### Q6. 网页内容抓取的优先级与去噪？
- **背景**：官网、ProductHunt、G2、Reddit、HackerNews 权重怎么排？
- **建议解法**：优先级 = 官网 > 评测站(G2/Capterra) > Reddit > 新闻
- **状态**：待研究
- **优先级**：🔴 P0

### Q7. 如何把非结构化文本抽成结构化字段？
- **背景**：价格信息可能藏在表格、博客、FAQ 里
- **建议解法**：用 Claude haiku + JSON Schema 约束输出，多个来源投票
- **状态**：待研究
- **优先级**：🔴 P0

### Q8. 信息时效性怎么保证？
- **背景**：价格 2023 年的过时了，怎么识别？
- **建议解法**：每个 source 带 `retrieved_at` + LLM 评估"信息新鲜度"
- **状态**：待研究
- **优先级**：🟡 P1

### Q9. 反爬怎么办？
- **背景**：某些站直接抓不到（Cloudflare、JS 渲染）
- **建议解法**：第一版用 Tavily 的 `include_raw_content`（它帮你抓），自己抓只做兜底
- **状态**：待研究
- **优先级**：🟡 P1

## 三、Prompt 工程

### Q10. 每个 Agent 的 prompt 怎么设计？
- **背景**：系统 prompt、用户 prompt、few-shot 例子？
- **建议解法**：每个 Agent 单独写 `prompts/{agent}.md`，方便迭代
- **状态**：待研究
- **优先级**：🟡 P1

### Q11. 怎么让 LLM 严格输出指定 JSON Schema？
- **背景**：Claude 的 tool use 还是 prefill assistant？
- **建议解法**：用 Claude 的 `tool_use` 模式，schema 即工具定义
- **状态**：待研究
- **优先级**：🟡 P1

### Q12. 报告生成怎么平衡"专业感"与"可读性"？
- **背景**：太学术枯燥，太口语化不专业
- **建议解法**：参考真实的咨询报告（艾瑞、易观）写 few-shot 模板
- **状态**：待研究
- **优先级**：🟡 P1

### Q13. 怎么让结论强制带引用？
- **背景**：LLM 容易"忘记"引用
- **建议解法**：prompt 里规定"每个事实陈述必须以 [src_id] 结尾"，后处理校验
- **状态**：待研究
- **优先级**：🟡 P1

## 四、引用追踪机制（核心创新点，必须研究透）

### Q14. sources 怎么从采集层贯穿到报告？
- **背景**：多个 Agent 处理后，怎么知道某条结论的原始 URL？
- **建议解法**：给每个 source 分配全局 `source_id`，所有 Agent 输出都带 id 引用
- **状态**：待研究
- **优先级**：🔴 P0

### Q15. 前端怎么实现"悬浮显示引用"？
- **背景**：报告里的 [1] [2] 怎么和 source 卡片对应？
- **建议解法**：Markdown 渲染时把 `[ref:id]` 解析成 `<Tooltip>` 组件
- **状态**：待研究
- **优先级**：🟡 P1

### Q16. 如何验证引用的真实性？
- **背景**：LLM 可能编造 URL，怎么避免？
- **建议解法**：所有 source 必须来自 Agent 真实采集到的列表，LLM 只能引用不能新增
- **状态**：待研究
- **优先级**：🔴 P0

## 五、用户体验与可视化

### Q17. Agent 进度动画怎么设计才有冲击力？

- **优先级**：🟡 P1

- **建议解法**：状态变更 + 关键节点（如"找到第 3 个竞品"）推送
- **状态**：待研究
- **优先级**：🟡 P1
